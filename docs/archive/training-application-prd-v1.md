# Training Application — PRD

*Creator Suite · Rebuilt from the project chat "Podcast to social media snippets workflow." The original formatted PDF is still downloadable in that chat.*

## 1. Summary

The Training Application turns a creator's live sessions — Zoom meetings, webinars, and uploaded video — into polished, YouTube-quality course videos, then hosts and sells those courses to students on the platform. It is a managed marketplace: students pay the platform, the platform pays creators and facilitators via percentage revenue shares, and platform-employed facilitators manage the delivery experience.

The app is the third product in the Creator Suite, sharing a media pipeline with the Podcast Clipper and consuming the Social Poster's publishing API for promotion. Its core differentiator is the creation side: "your Zoom recordings become a sellable course automatically." Delivery is deliberately lean; the product does not compete feature-for-feature with legacy LMS platforms.

## 2. Problem

Subject-matter experts already teach live — coaching calls, workshops, internal trainings — but turning those recordings into sellable course content requires editing skills, publishing infrastructure, payment handling, and student support that most creators don't have and don't want. Existing options force a choice: heavyweight LMS platforms (Kajabi, Teachable) that still leave all production and delivery work to the creator, or agencies that are expensive and slow.

## 3. Goals and Non-Goals

### Goals
- Zero-effort ingestion: a completed Zoom cloud recording becomes a draft course lesson without the creator touching a file.
- Automated production: transcription, dead-air removal, chaptering, titles, descriptions, and thumbnails generated by the media pipeline.
- Simple, reliable delivery: ordered lessons, secure streaming, progress tracking, magic-link student access.
- Centralized commerce: platform is merchant of record; all student payments flow to the platform.
- Trustworthy money handling: immutable earnings ledger, versioned percentage splits, automated payouts to creators and facilitators.
- Facilitator operations: assignment, scoped access, and performance visibility for platform-paid facilitators.

### Non-Goals (v1)
- Creator-branded sites or custom domains.
- Direct student-to-creator payments (no Stripe Connect checkout on behalf of creators; Connect is used for payouts only).
- Quizzes, certificates, gamification, or community features.
- Live streaming or real-time classes (ingest is recorded content).
- Multi-currency pricing (single currency at launch).

## 4. Users and Roles

| Role | Who | Primary jobs |
|---|---|---|
| Creator | Subject-matter expert who records content | Connect Zoom, review generated lessons, assemble and price courses, track earnings |
| Student | End learner who purchases a course | Buy, watch, resume progress, get help from a facilitator |
| Facilitator | Platform-paid delivery manager | Manage assigned courses/cohorts, support students, monitor completion, earn revenue share |
| Admin | Platform operator | Approve creators, set split policies, run payouts, refunds, oversight |

## 5. Product Description

### 5.1 Content Creation

The creation half is a head on the shared Creator Suite media pipeline (ingest → transcribe → LLM analysis → render → publish).

- **Ingest:** Zoom cloud-recording webhook (primary), direct video upload, and Google Drive folder watch. Recording completes → pipeline fires automatically.
- **Transcription:** Whisper with word-level timestamps; transcript stored per lesson and used for chapters, search, and captions.
- **AI production:** LLM pass produces chapter markers, dead-air / filler cut list, lesson title and description, and thumbnail prompts; structured JSON output validated before render.
- **Render:** FFmpeg on GPU-backed workers applies cuts, burns captions (optional), assembles intro/outro, outputs streaming-ready video. Render jobs run in a dedicated worker pool separate from web infrastructure.
- **Review:** creators see a draft lesson with editable chapters/title/description and approve before it becomes publishable.
- **Promotion:** approved lessons can generate social clips and captions dispatched through the Social Poster API.

### 5.2 Delivery

- **Course structure:** a course is an ordered list of lessons (video + description + attachments). Draft → published → archived lifecycle.
- **Streaming:** video served via a hosted streaming provider (Mux or Cloudflare Stream) with signed URLs; no self-hosted video delivery.
- **Student access:** purchase creates an enrollment; students authenticate via magic link; access is enrollment-gated per course.
- **Progress:** per-lesson completion tracking and resume position.
- **Facilitation:** each course/cohort has assigned facilitators with scoped visibility into their students, completion rates, and a student-question inbox.

### 5.3 Commerce and Payouts

- Platform is merchant of record. Checkout via Stripe (with Stripe Tax) or a merchant-of-record provider; decision tracked as an open question.
- Every sale records gross, tax, and processor fees; splits are computed on **net** in basis points.
- Split policies are versioned as complete sets per course (creator + facilitator(s) + platform = 100%); changes apply only forward.
- Immutable append-only earnings ledger; refunds are negative mirror entries; rounding remainders absorbed by the platform share.
- Payout runs sweep unpaid ledger balances per party and transfer via Stripe Connect Express (automated tax-form handling).

## 6. Key User Flows

- **Creator onboarding:** apply → admin approves (role change) → connect Zoom + Stripe Connect → first recording ingested automatically.
- **Recording to lesson:** Zoom webhook → pipeline job → draft lesson → creator review/edit → approve → attach to course.
- **Purchase:** student checkout → payment webhook → sale recorded → enrollment created → ledger splits written → welcome email with magic link.
- **Facilitation:** admin assigns facilitator to course → facilitator sees roster and progress → handles student questions → earns per-sale share.
- **Payout:** scheduled run computes balances → creates payout records → Stripe Connect transfers → parties see payout history and statements.
- **Refund:** admin triggers refund → processor refund + negative ledger entries → enrollment revoked (configurable).

## 7. Functional Requirements

### Ingestion & Production
- **FR-01** — Zoom OAuth connection per creator; cloud-recording-completed webhooks trigger ingestion with no user action.
- **FR-02** — Direct upload of video files (mp4/mov) and audio (mp3/m4a) up to 4 hours.
- **FR-03** — Whisper transcription with word-level timestamps; transcript editable and stored per lesson.
- **FR-04** — LLM production pass returns validated structured JSON: chapters, cut list, title, description, thumbnail prompt; invalid output retried with error feedback.
- **FR-05** — GPU render workers apply cuts, captions, intro/outro; job status visible to the creator; failed jobs retryable.
- **FR-06** — Creator review screen to edit chapters/title/description and approve or re-render before publishing.

### Courses & Delivery
- **FR-07** — Course CRUD for creators: ordered lessons, pricing, draft/published/archived status.
- **FR-08** — Streaming via signed URLs; playback gated by enrollment.
- **FR-09** — Magic-link student authentication; students see only enrolled, published courses.
- **FR-10** — Per-lesson completion and resume position tracking.
- **FR-11** — Facilitator assignment per course; facilitators see only assigned courses, their rosters, and progress metrics.
- **FR-12** — Student question inbox routed to the course's facilitators.

### Commerce, Ledger & Payouts
- **FR-13** — Checkout collects payment to the platform account; sale records gross, tax, processor fee, net, currency, and processor reference.
- **FR-14** — Successful payment atomically creates enrollment and writes split ledger entries from the policy set effective at sale time.
- **FR-15** — Split policies stored in basis points, versioned as complete sets summing to exactly 100%; admin-managed.
- **FR-16** — Ledger entries are append-only; the only permitted mutation is one-time payout assignment; refunds create negative mirror entries.
- **FR-17** — Payout runs sweep positive unpaid balances per party, create payout records, and execute Stripe Connect transfers; concurrent runs cannot double-pay.
- **FR-18** — Creators and facilitators see earnings statements: per-sale entries, balances, and payout history.
- **FR-19** — Admin console: creator approval, split management, refunds, payout oversight, facilitator performance dashboards.

## 8. Non-Functional Requirements

- **NFR-01** — Row-level security enforces the four-role access model on every table; money tables accept writes only via service role or security-definer functions.
- **NFR-02** — Financial invariants enforced in the database (split sums, ledger immutability, payout locking), not application code.
- **NFR-03** — Render workers scale independently of web infrastructure; a 60-minute recording renders in under 30 minutes.
- **NFR-04** — Pipeline jobs are idempotent and resumable; a failed step never duplicates ledger entries, enrollments, or renders.
- **NFR-05** — All video delivery via signed, expiring URLs; no public object storage for course content.
- **NFR-06** — Webhook handlers (Zoom, payments) are verified, idempotent, and safe under retries.

## 9. System Architecture

Monorepo (pnpm) shared across the Creator Suite:

- **packages/core** — tenancy (org → members → audiences), auth, billing primitives, shared UI.
- **packages/media-pipeline** — job queue (pg-boss/BullMQ), ingest adapters (Zoom, upload), Whisper, LLM steps, FFmpeg render dispatch to GPU worker pool.
- **apps/trainer** — this product: creation head, course delivery, commerce, facilitator tooling.
- **apps/poster** — consumed via internal API for social promotion of published lessons.

Platform services: Supabase (Postgres, auth, storage, RLS), Stripe (checkout, Tax, Connect payouts), Mux or Cloudflare Stream (video delivery), GPU render workers (Modal / dedicated boxes). Database schema for roles, courses, sales, split policies, ledger, and payouts is defined in migrations 001–004 (companion to this document).

## 10. Milestones

| Milestone | Scope | Exit criteria |
|---|---|---|
| M1 — Creation | Zoom ingest, pipeline, render, creator review | A real Zoom recording becomes an approved, watchable lesson with zero manual editing |
| M2 — Delivery | Courses, enrollment, streaming, progress, magic-link auth | A test student purchases (test mode), watches, and resumes a course end-to-end |
| M3 — Marketplace | Live payments, ledger, splits, facilitator tooling, payout runs | First live sale produces correct ledger entries; first automated payout reconciles to the cent |
| M4 — Promotion | Social Poster integration, clip generation from lessons | Publishing a lesson can dispatch promotional clips to connected social accounts |

## 11. Success Metrics (recovered subset)

- Time from recording end to approved lesson (target: creator touches it once, under 10 minutes of review).
- Creator activation: % of approved creators with a published course within 30 days.
- GMV, take rate, and net revenue per course.
